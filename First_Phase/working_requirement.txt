## 一、项目目标

用户自然语言指令
→ Hermes Harness 调用 VLM 理解指令与相机画面
→ 感知工具定位目标物体

第一阶段只做仿真，不连接真实机械臂，不要求训练模型。先实现一个简单桌面抓取任务，再扩展到“拿起指定杯子并放到指定区域”。

最终希望迁移到 SO-ARM101 真机，因此应保持感知、规划、控制和任务接口相互独立。

## 四、模块职责

### 1. Hermes 与 VLM

- Hermes 负责工具调用、任务状态管理和流程组织。
- VLM 负责理解用户意图、选择目标物体、解释结果及提出重试策略。
- 先确认选择的 VLM 支持图像输入，Hermes 的调用链能够实际传递图像。
- 不让 VLM 逐帧输出关节指令。
- 不让通用 VLM 凭空给出的坐标直接进入控制器。
- VLM 可以调用检测、分割、定位、抓取规划等专用工具。

### 2. 感知与几何计算

输入包括 RGB、对齐的深度、相机内参，以及相机到机器人基座的坐标变换。

实现：
- 目标检测或分割；
- 从目标区域的有效深度计算三维点；
- 从相机坐标系转换到机器人基座坐标系；
- 输出位置、必要的几何信息、置信度或失败原因。

明确区分物体表面点、物体中心、物体姿态和抓取姿态。不要简单认为检测框中心反投影后就是正确抓取点。

坐标系、单位、深度含义和时间戳必须统一。无效深度、遮挡或过期观测应有明确处理方式。

### 3. 抓取与运动规划

- 第一版可以使用规则或几何方法生成候选抓取姿态，不要求训练抓取模型。
- 候选包含夹爪位置、朝向、开合宽度、接近方向和抬起动作所需参数。
- MoveIt 2 负责运动学求解、可达性检查、碰撞检查和轨迹规划。
- 尽量复用 MoveIt Task Constructor 或成熟抓取示例。
- 正确配置机器人模型、关节限制、碰撞模型、夹爪和控制接口。

### 4. 仿真执行与结果验证

- 使用真实的物理仿真，不以动画播放替代抓取验证。
- 机械臂、夹爪、物体和桌面应具备适当的碰撞与物理属性。
- 将 MoveIt 轨迹转换为仿真控制器能够执行的指令，并读取执行反馈。
- 区分“轨迹执行完成”和“物体成功抓取”。
- 不通过直接修改物体位置或无条件把物体固定到夹爪来伪造抓取成功。
- 规划场景中的物体附着状态与仿真中的真实接触结果应分别处理。

## 五、工具接口

先建立普通 Python 模块或服务接口，独立测试通过后，再暴露给 Hermes。优先评估 MCP 或 Hermes 官方支持的扩展机制，选择最简单且可靠的方式。

可以参考以下工具职责，但不必机械照搬命名：

- observe_scene：获得当前观测。
- locate_object：根据目标描述返回定位结果。
- propose_grasps：生成抓取候选。
- plan_grasp：验证候选并规划动作。
- execute_plan：执行已验证的计划。
- get_execution_status：查询进度。
- verify_task：检查任务结果。
- reset_scene：重置仿真。
- stop_execution：停止执行。

接口需要：
- 明确的输入输出结构；
- 坐标系和单位说明；
- 超时、失败原因及日志；
- 观测与计划的关联，避免执行过期计划；
- 区分工具调用失败、规划失败、执行失败和任务失败。

长动作可以返回执行编号，再查询状态。仿真场景应持续存在，不要每次工具调用都重新创建场景，导致任务状态丢失。

## 六、按阶段实施

### 阶段 A：底层执行基线

暂时使用仿真中的准确物体位置，验证：
- 机器人与夹爪可控制；
- MoveIt 能规划并执行；
- 一个简单物体能被实际抓起和放下。

这里使用准确位置只是调试基线，需要明确标记。

### 阶段 B：视觉闭环

用 RGB-D 感知替代准确物体位置。仿真真实状态仅用于评估，不作为视觉模块的隐藏输入。

测试不同物体位置，记录定位误差与抓取效果。

### 阶段 C：完整 Agent 链路

接入 Hermes 和 VLM，用户用自然语言指定目标，Agent 调用工具完成任务并报告真实结果。

先支持有限、明确的任务范围，不承诺任意物体、任意指令都能完成。

### 阶段 D：失败反馈与重复测试

加入有次数上限的重新观察、换抓取候选和重试流程。

记录：
- 目标选择是否正确；
- 规划是否成功；
- 抓取、放置是否成功；
- 完成时间；
- 重试次数；
- 失败类型。

第一版不需要 RL。不要为了使用 RL 而额外引入 RLinf。后续只有在失败分析明确指出需要学习的模块后，再讨论训练对象、观测、动作、奖励和训练方法。
