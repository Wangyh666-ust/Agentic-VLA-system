## 2. 必须实现的目标

1. 接入真实的预训练 VLA，并根据机器人、场景和任务需要适配或微调。图像、语言与机器人状态必须实际进入策略；运动动作必须由策略生成，不能将 VLM 调用抓放脚本称为 VLA。
2. 建立底层短段动作反馈循环与高层任务／恢复循环。执行中使用新观测，处理抓空、目标移动或状态偏离，而不是只在初始阶段看一次图。
3. 先独立验证直接 VLA 的基础操作能力，再接回 Hermes。保留现有脚本系统作为对照，避免混淆底层策略能力与高层 Agent 的贡献。
4. 逐步覆盖抓起、放到区域、红块放到蓝块上，以及受扰后的恢复。不要承诺预训练模型开箱即用，也不要以单次演示代替可靠性评测。

## 3. 建议的整体架构

```text
用户任务
  |
  v
Hermes + 高层模型
  目标理解 / 支持的子任务选择 / 阶段判断 / 恢复决策
  |
  v
VLA 执行服务
  新鲜图像 + 关节状态 + 支持的语言子任务 -> action chunk
  |
  v
动作适配器 -> 仿真控制器 -> 机器人
  ^                            |
  |                            v
  +------ 下一次策略输出      新观测 -> VLA 执行服务

VLA 执行服务 -- 阶段状态、失败原因与观测摘要 --> Hermes
```

底层循环应执行一小段动作、获取新观测、再次推理。将模型输出的 chunk 长度与实际执行长度分开配置；不要默认执行完整的长动作序列后才重新观察。动作队列需要取消、过期与异常处理机制，避免目标改变后继续执行旧动作。

高层循环在阶段结束、异常或约定的检查点介入，不应每个物理步都调用大模型。高层工具调用延迟与底层控制频率需要解耦。

VLA 本身不会自动获得倒伏恢复能力。闭环机制只提供利用新观测的条件，具体恢复仍取决于策略训练覆盖、任务表示、观测质量和高层支持的恢复行为。

| 现有部分 | 建议处理方式 |

| Hermes、MCP、日志 | 保留框架思路，调整为支持有边界的策略执行与状态反馈的契约 |
| 相机与机器人状态采集 | 保留功能，适配所选策略的观测格式、视角和时间同步要求 |
| HSV 定位、propose_grasps、几何抓放脚本 | 保留作基线、诊断或明确标注的专家数据来源，不冒充 VLA |

## 5. 候选路线与选择门

建议主实验回到 ManiSkill，优先评估 SO-100 + SmolVLA／LeRobot，保留当前 Gazebo 实现用于工程对照。**这只是优先调查的组合，不是已经验证兼容的组合。** ManiSkill 提供 SO-100 任务，不意味着 SmolVLA 的某个 checkpoint 可以直接控制该环境。

请联合检查以下条件，形成兼容性矩阵并选定一个主方案：

- 模型权重可用性、许可证与版本；
- 机器人构型、关节与夹爪定义；
- 观测、动作表示、归一化与时序；
- 训练数据来源、目标任务覆盖与适配成本；
- 实际 GPU 显存、推理延迟、训练成本；
- 仿真环境、维护成本与后续真机迁移边界。

SmolVLA 是约 450M 参数的候选，OpenVLA-OFT 是原计划候选，均不是必须选用或保证可运行的承诺。若另一成熟机器人／权重组合明显降低验证风险，可以先验证架构，但必须明确 SO-101 尚未适配，不能把替代机器人结果当作目标硬件结果。

若当前 Gazebo 路线更现实，可以暂留，但需解释与原计划的差异、可复用边界及以后迁移成本。不要同时盲目安装多套大型环境，也不要在缺乏证据时通过换更大模型解决问题。

GPU 推理、GPU 渲染和 GPU 并行物理仿真是不同能力，请分别确认。推理显存、延迟与微调成本应实测；文档中的 24 GB 主机内存不能当成 GPU 显存。

## 6. 接口与时序核对表

在正式运行策略前，逐项记录并验证：

| 类别 | 必须明确的内容 |
| --- | --- |
| 图像 | 相机数量、视角、RGB 通道顺序、分辨率、预处理、时间戳 |
| 机器人状态 | 关节名称与顺序、单位、零位、上下限、夹爪方向 |
| 动作 | 绝对关节目标、关节增量还是末端动作；坐标系、维度、单位、归一化与反归一化 |
| 时序 | 仿真 dt、控制频率、策略推理频率、chunk 长度、实际执行长度、推理延迟、过期动作处理 |
| Episode 生命周期 | reset 时清理策略历史、缓存、动作队列与执行状态 |

接口维度一致不等于策略适配成功：相机布局、物体外观、动力学、任务指令和状态分布仍可能偏离训练分布。

可参考以下工具划分：

- `observe_scene`：获取允许使用的当前观测；
- `execute_skill(instruction, budget)`：启动受预算约束的策略执行；
- `get_execution_status`：获取执行进度与状态；
- `stop_execution`：取消执行并清理待执行动作。

以上仅为概念契约，不是当前已实现 API。请根据代码确定确切参数、类型与返回结构。状态至少应能区分 `running`、`succeeded`、`failed`、`stopped`，并携带失败原因、进度和时间戳。“执行完成”不等于“任务成功”。高层不能假定任意 `grasp`／`release` 等语言指令都受所选 checkpoint 支持。

## 7. 数据与策略适配

先检查现有权重与环境匹配性，再决定是否需要采集数据和微调。需要适配时，在目标仿真中通过遥操作或经过验证的专家收集成功示范，记录图像、机器人状态、动作、语言、时间戳与终止信息。

训练、验证和测试应按场景或 episode 划分，避免将同一轨迹的相邻帧分到不同集合造成泄漏。位置变化、语言变化与倒伏恢复需要有对应的数据覆盖，不能只采标准直立抓放后期待复杂恢复自然出现。

现有失败较多的脚本不能未经验证就作为成功专家。可以保留原始失败数据用于分析，但必须标注并与成功示范区分。官方示例中约 50 条示范只能作为简单任务的起点，不是堆叠和恢复能力的保证。

当前优先采用预训练策略加必要的模仿学习适配，不从零训练基础模型，也不默认开展 VLA 强化学习。正式研究中的高层强化学习另行评估。在比较不同高层方案时冻结底层策略，避免将策略变化混入 Agent 效果。

## 8. 实施阶段与推进门槛

### A. 只读核实现状与方案决策

检查实际仓库、执行入口、环境版本、GPU、模型与数据条件，形成现状审计、兼容性矩阵和一个主方案。先完成必要的兼容性验证，再下载大型权重或开展训练。

### B. 最小仿真与真实策略接口往返

建立最小任务环境，完成真实策略推理与动作执行。日志必须能证明图像像素、机器人状态和指令进入策略，并能对应模型输出、适配后的指令及实际执行动作。不能仅用随机动作或脚本动作证明“VLA 已接入”。

### C. 独立 VLA 基线

先完成简单抓起，再完成放到区域；暂不依赖 Hermes 补救底层不足。固定测试配置，覆盖多个初始状态，报告样本数、成功率、耗时和失败类别。

请在测试前确定与项目目标相符的数值门槛及样本规模，记录依据；不得测试后临时改变门槛或挑选成功样本。未达到门槛时先定位感知、动作适配或策略能力问题。

### D. 接回 Hermes 并进行公平对照

比较直接 VLA、固定高层计划、固定重试及观测驱动恢复。保持底层 checkpoint、测试任务、初始状态分布和评估器一致，并明确限制各方法的总执行时间、动作预算与重试机会，避免预算差异制造优势。

### E. 堆叠与受扰恢复

逐步加入红块放到蓝块上，以及物体位移、抓空、倒伏等干扰。记录扰动方式、发生时刻和强度。episode 内不得通过复位场景伪装恢复；输出恢复率、恢复耗时和失败类型。

各阶段未达门槛时，应解释问题并修正对应环节，不要用更复杂的 Agent 掩盖低层动作缺陷。

## 9. 评估原则与真实验收

仿真真值仅供独立评估器使用，或用于明确标注的 oracle 调试条件。不得静默把物体真值位置、姿态或成功标志输入主视觉策略或 Agent，以此冒充视觉闭环。在线控制反馈应来自实验定义中允许的传感器；oracle 结果必须单独报告。

放到区域与稳定堆叠必须有不同判据。堆叠应检查支撑关系、相对位置与高度、稳定保持、夹爪释放，不能仅凭平面距离较小判成功。抓起过程也应独立评估，避免把撞入目标区域算作正常抓放。场景 reset 仅发生在 episode 之间。

至少报告正常条件成功率、扰动条件成功率、恢复率、动作／推理延迟、任务耗时和失败类别，并说明各指标的分母和超时处理。

最终验收应有以下证据：

- 使用真实 VLA，且视觉、语言、状态与动作链可追溯；
- 主评测中没有脚本暗中接管，任何回退机制均明确标注并单独统计；
- 执行中持续获取新观测，存在短段执行与动作取消／过期机制；
- 恢复实验不在 episode 内复位，能区分尝试恢复与实际恢复成功；
- 独立评估器与策略／Agent 的真值使用边界明确；
- 启动、评测、日志和结果可以复现。

模型加载成功、机械臂能够运动或某次任务成功，均不足以宣称整个改造完成。无法完成的环节应如实列出，不虚构性能数字、测试结果或兼容结论。
