# 微小越界接管修复与灶台红圈检查：两组实测

**本轮碗→酒瓶、碗→灶台各新执行一次，两个组合均完整通过。四个子任务都实际执行了开爪命令、退离和原归位，最终目标保留、夹爪张开、无手部接触，独立连续五次确认通过。**

这次解决的是前一轮的两个入口故障，没有重新设计归位，没有单独运行归位实验，没有微调，也没有使用子 agent。使用已有的 LIBERO 原始 goal_table 场景（robosuite/MuJoCo、Franka Panda，seed0/init0）及预训练 SmolVLA；顺序由用户指定，因此不是 Hermes 自主规划增益的测量。

## 酒瓶：相同越界读数，这次接管成功

前轮左指实测 `0.04001874449002873 m`，比执行器指令上限 `0.04 m` 多 `0.01874449 mm`，严格检查拒绝控制器启动。**本轮第300步移交前仍是完全相同的这组读数，修复后的控制器成功接管，并实际退离、归位。**

修复在 `safe_exit._finger_hold`：保留真实实测值，只把生成的保持目标限制在合法的执行器指令范围，再转换为合法的归一化指令。没有改写仿真关节状态，没有删除有限值、接口映射检查，也没有取消路径保护。该公共函数的收尾与安全退出调用都使用同一修复。

酒瓶第150个VLA动作，Qwen仍返回：

```json
{"goal_achieved":false,"reason":"sideview显示酒瓶仍在机械臂夹爪上，未放置到架子上"}
```

按原定检查配置继续到300步，真实回答：

```json
{"goal_achieved":true,"reason":"sideview图像清晰显示酒瓶已稳定放置在架子上"}
```

此时VLA已经张开夹爪；收尾器再发出标准开爪命令，完成退离和原归位。最终Qwen再次确认酒瓶在架子上，独立五连通过。不能把这次结果说成“收尾器替VLA完成了酒瓶第一次松手”，也不能说第150步的视觉判断问题已全部消失。

## 灶台：识别红圈，触发开爪与退离

为 `catalog` 中的灶台资产补充静态视觉定义：红色加热圈亮起表示开启；炉面清晰可见且红圈熄灭表示关闭。该定义不包含当前状态，不预告任务成功。只在对应开关子任务的提示词中加入；夹持/开口仍由同步编码器决定。

第150个VLA动作，Qwen实际回答：

```json
{"goal_achieved":true,"reason":"sideview中灶台炉面显示亮起的红色加热圈"}
```

于是收尾器真正启动。最初20次开爪命令后，一侧手指仍未到标准开口，既有的同时开爪退离分支被触发。实际 `concurrent_open_retreat.triggered=true`；退离期间继续发送标准开口目标，手指从受接触限制的状态张开。36步退离后调用原归位，实际执行106步，最终开口、关节姿态、无接触与两个目标均通过。

这次退离仍保留回程路径检查：26步时回程预测有碰撞，没有贸然归位；继续退离至36步，回程检查通过后才进入归位。无需改动旧归位控制器，也没有额外增加新的停止门槛。

原来的微小越界启动阻断已在原故障读数下解除；灶台红圈在本轮被正确识别，并真正触发了收尾及原归位。**这两个指定组合的执行链路本轮已跑通。**
