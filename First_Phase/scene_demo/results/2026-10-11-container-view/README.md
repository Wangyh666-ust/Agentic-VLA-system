# 新场景小试：番茄酱入篮、杯子入炉→关门

**当前两类任务都没有完整跑通。关门没有启动，不能报告为“关门成功”或“关门技能失败”。**

本轮按用户要求增加这两个原生场景。初测发现外部检查相机漏掉篮子、主要拍到微波炉背面，保留初测后修正检查输入，各补测一次。这里展示补测结果；[初测报告与视频](../2026-10-11-container-pilot/README.md)也完整保留。

| 补测 | 到了哪一步 | 检查器回答 | 收尾 / 归位 / 后续 |
|---|---|---|---|
| 番茄酱入篮 | 新VLA150步，目标仍在桌面、未入篮 | 理由说“未进入篮子”，返回值却是null | 未开爪、未退离、未归位；第150步提前停止 |
| 杯子入炉→关门 | 新VLA300步，杯子仍被夹着、在入口附近；未满足入炉目标 | 第150步false，第300步null | 未开爪、未退离、未归位；关门未启动 |

“未触发收尾”与“收尾执行失败”不同。本轮修正后的两个样例都没有形成已验证的到位正例，收尾动作数为0，**收尾效果未验证**。这次失败没有发生在原归位控制器里。

补测实际发送同一时刻的wrist与agentview，后者是原生正面外部相机，名称未伪装成sideview。夹爪编码器、图片与机器人反馈的时间、图像哈希全部匹配；发送提示词没有phase/stage标签，仿真目标与接触清单没有发送给Qwen。完整提示词、原始响应、实际图片路径和逐项审计见[summary.json](summary.json)及其中request_path。

独立记录也没有发现成功位置：番茄酱150次、杯子300次VLA动作后的原生入篮/入炉目标均为假。杯子末态接触筛查显示仍持有white_yellow_mug_1，phase为holding_target_outside_goal；编码器尚未达到标准开口。闭合本身没有被当成“持物”的唯一依据。这些是独立诊断，未用作检查器输入。

## 修了什么，哪些问题还在

1. **相机输入已修正。** 新场景使用同时保存、覆盖目标的agentview；VLA输入相机、策略、控制、路径几何和原归位没有改变。
2. **补测避免了初测的错误松手。** 初测杯子第300步被误报在炉腔内，实际开爪9、退离26、确认2、归位107，杯子最终落在炉外桌面。原归位五连通过，但入炉独立五连为0，故没有执行关门。补测没有强行开爪。
3. **检查器的false/null语义仍不稳。** 已说“目标在桌面/入口外”，却因另一视角看不清而返回未知。提示中“看不到所需位置关系返回null”仍可能被混同为“没看到目标关系成立就返回null”。本轮没有额外请求做提示词消融，不能断言这就是唯一原因。
4. **底层搬运也未完成。** 杯子在本轮300动作预算内没有进入炉内。番茄酱仅执行到150动作，不能断言它继续到300也一定失败。当前原子指令不是微波炉原生完整复合指令，未经匹配训练语言的对照，不据此认定训练缺陷。

下一步先把检查器规则说清：任一视角清楚显示目标未到位就返回false；只有确实无法判断才null，另一视角遮挡不应自动否决清楚的证据。明确第150步未知是否只“不移交收尾，继续VLA至300”，而不是提前停止。此规则**尚未实施或实测**。再针对实际搬运失败核查指令与已有训练任务的对应，复用已有番茄酱基线，不立即微调、不重复归位测试。
