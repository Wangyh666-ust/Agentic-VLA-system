# 统一子任务辅助：接口已接通，接近准备未过效果验收

本轮建立了统一入口：Hermes决定对象和子任务顺序；harness在每个子任务开始时读取最新状态，根据操作、形状、姿态及已验证证据选择辅助；之后同一SmolVLA继续执行。辅助器已能为碗选择通用接近准备，未把酒瓶侧抓套给碗。**但这轮准备动作还未成功，不能说已改善组合任务。**

## 四次小范围对照的结论

两组都从已保存的“酒瓶放好、接着抓碗”状态出发；每组启用/禁用辅助的真实初始状态SHA和模型种子相同。它们是两个交接状态的四次碗执行，复用了旧Hermes计划；本轮没有新的Hermes请求，不是四个新场景或总体规划能力评测。

| 交接状态 | 关闭辅助 | 开启辅助 |
| --- | --- | --- |
| case02 / seed2 | 500个VLA动作，未抓起碗、未放置成功 | 143个准备动作，调整朝向超时；VLA动作0 |
| case03 / seed3 | 500个VLA动作，未抓起碗、未放置成功 | 144个准备动作，调整朝向超时；VLA动作0 |

两条辅助路线都完成退出货架附近和升高，在约1.466米的高度调整夹爪方向时停住，还没有移动到碗旁。停止时位置误差约0.46/0.58毫米，朝向误差约8.0/7.6度；准备门要求位置5毫米以内、朝向约2.9度以内并连续五次真实动作后检查通过。由于没有达到准备位，本轮**没有有效的“准备后VLA抓碗”样本**，不能判定准备对VLA有益或无益，也不能归因于训练缺陷。

四次末态的酒瓶目标保持为真；所有实际采样的碗抓取为真次数和抬高至少3厘米次数均为0；原酒瓶目标在采样中没有假/未知。灶台关闭与奶酪5毫米保护评分均通过。完整独立Gold（碗在盘子上且酒瓶在架子上，加原释放/稳定检查）四次均未达成。原JSON里的report.ok=true只表示四次协议执行完整、输入一致、没有程序运行错误，**不表示任务成功**。

## 做了哪些改动，哪些还没证明

统一context、仿真几何观察、通用接近控制器和每子任务执行入口已经实现。名称只用于找到对象，策略选择采用操作/几何及校准证据。低宽碗当前仅准备加原VLA；验证过的酒瓶策略仍使用原能力适配器，尚未验证任意同形状物体的抓取。准备后清队列与最新观测、动作预算、持握/保护/取消等已通过软件测试。

离线路径最初因粗略包围盒误判重叠而被拒绝，现用真实碰撞网格凸包的分离间隙进一步筛查，安全间隙阈值保持不变。两例实际源码离线检查通过，但实际朝向动作仍超时。路径碰撞检查和整条机械臂的可达性/控制收敛是不同条件；当前路径只预检查夹爪几何，完整机械臂仅监测实际接触。

67项新测试（另有3项子测试）与77项既有回归通过。物理运行15分33秒，新增动作1287个（VLA1000、准备287）；重放旧动作1388个只用于还原状态；模型载入一次，无微调、无重试、无扩大场景。评判采用运行前固定的独立Gold，保持原release_verified完成条件。

## 接下来应该处理什么

优先检查准备阶段的朝向控制接口与关节余量，增加位姿可达性检查，并选择机械臂实际能达到的转向位置。对于碗这样的目标，还应评估是否可以保留其允许的水平转角，减少额外旋转。当前证据只证明给定路线和预算下调整方向未达到要求，尚未证明是关节极限或某个确定原因。先获得有效准备动作，再比较接回VLA后的抓取；暂不训练。
