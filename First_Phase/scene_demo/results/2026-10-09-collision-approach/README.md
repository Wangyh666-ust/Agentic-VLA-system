# 酒瓶抓取前的避碰修正：一个失败状态的对照（2026-10-09）

本报告只测一个既有的失败起始状态：在该局部抓取中，旧路线未成功，v1 仍未成功，v2 抓取并抬起 2.73 cm。运输与置架任务在本轮未测试；因此不能据此断言整个组合任务已修复，也不能声称已部署、可靠或有训练缺陷。

## 旧路线、v1、v2 对照

| 项目 | 旧路线 | v1 | v2 |
|---|---|---|---|
| 结果 | 失败 | 失败（route_timeout） | 抓取并抬起 2.73 cm |
| 辅助动作数 | 11 | 50 | 191 |
| 接近阶段最大酒瓶转角 | — | 4.18° | 4.18° |
| 接近接触采样 | — | 0 | 0 |
| 抓取 | 否 | 否 | 是 |
| 放置 | — | 未测 | 未测（placement_task_success 为 null） |

旧路线辅助动作 11 次，第二个辅助动作后记录到夹爪右侧手指与酒瓶接触，酒瓶累计旋转 20.18°，失败。v1 在 50 个动作后路线超时，最大接近转角 4.18°，接近接触采样 0，无抓取。v2 本地动作共 191 次：接近 146 次（58 逃逸 + 37 旋转 + 51 接近），下降 24、闭合 10、抬起 11；最大接近转角同样 4.18°，接触采样 0，确认夹爪持有酒瓶，抬起 2.73 cm。连续五次动作后检查，都确认夹爪仍夹住酒瓶，且酒瓶已抬离桌面；之前放好的碗仍在盘子上。确认抓取不等于已放置；placement_task_success 仍为 null。

## 起始状态与路线

同一物理起始状态由实际回放重建：碗 104 个动作 + 酒瓶 120 个动作 = 224 个动作；旧路线、v1、v2 在辅助器接手时的完整物理状态哈希完全一致，记录见两份候选 report.json。接近路线分成三段：保持当前朝向退出并抬高；留出空间后调整夹爪朝向；再从侧面接近。随后夹紧酒瓶并抬起。最终旧侧向抓取目标不变。v1 高度 1.265 m 过于保守；v2 按本次所需约 39° 的转腕角度估算夹爪扫过的空间，保留避碰余量，将目标高度降到 1.199 m。逃逸预算由每条路线 50 提到 60，整体接近由 130 提到 150；全局辅助上限 200 与旧的 15 mm/20° 保护限值没有放宽。77 个 CPU 测试通过。

## 限制

这些测量来自一个起始状态、两个修订版，不是两个独立任务，也不是一般成功率。接触采样 0 只表示真实动作后的观测，并不覆盖所有物理子步，也不构成任意时刻无碰撞的证明。这次共用了 191 个辅助动作，已经接近 200 个动作的总上限，执行仍然偏慢。本轮新增 Hermes/VLA 推理调用为 0；已有 VLA 动作只是被回放。没有训练或微调。生产默认与 UI 未切换。与 LocalGraspController 兼容的模块可以注入 collision_grasp，但本报告不作部署声明。坐标与碰撞几何来自 MuJoCo；RGBD 感知未实现。后续仅建议把抓到的物体送回 VLA 运输/置架，并测试少量其他起始状态；目前不再新增运行。

## 分工与边界

开发侧 GPT 负责诊断、设计与验收，实际 DeepSeek 代码实现；运行时的 Hermes 与 SmolVLA 是另一层，不要混淆。本次实验新增 Hermes/VLA 调用为 0。不要把监测到的抓取确认当成基准放置成功，也不要声称辅助器创造全部机器人技能。
