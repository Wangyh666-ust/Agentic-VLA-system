# 完整归位后再执行第二任务：两例均成功

这次尝试成功了。保留已放在架上的酒瓶，让机械臂通过真实运动回到标准初始关节角、张开夹爪并停稳，再把碗任务交给 SmolVLA。两个之前失败的酒瓶后场景都完成了放碗和松手。

## 最直观的对照

| 条件 | 场景／模型种子 | 准备动作 | 新 VLA 动作 | 结果 |
|---|---:|---:|---:|---|
| 旧：不做准备，直接抓碗 | 同一两个酒瓶后状态／2、3 | 0 | 各500 | 两例均未抓起碗 |
| 旧：辅助器引到碗上方 | 同一两个酒瓶后状态／2、3 | 各164 | 各336 | 两例均未抓起碗 |
| 新：完整关节归位，再抓碗 | 状态2／2 | 243 | 93 | 碗放到盘子上、松手，酒瓶保留 |
| 新：完整关节归位，再抓碗 | 状态3／3 | 241 | 105 | 碗放到盘子上、松手，酒瓶保留 |

旧结果来自[关闭辅助对照](../2026-10-09-subtask-assist/README.md)与[通用准备对照](../2026-10-09-subtask-assist-repair/README.md)，本轮没有重跑它们。新 VLA 的额度是336步，与旧通用准备对照相同；归位另有最多360步。因此这里不能把关闭辅助的500步背景结果叫作相同总预算的重跑对照，也不能据两个案例宣称普遍成功率或效率提升。

## 这次具体做了什么

实际顺序是：恢复旧记录的酒瓶完成状态 → 确认酒瓶在架上、夹爪空着 → 机械臂真实归位并张开夹爪 → 等它停稳 → 清空策略及前后处理队列，重新读取最新画面 → 用原来的 SmolVLA 执行放碗 → 独立检查结果。

参考角度在酒瓶动作开始前，从曾成功完成单碗任务的原生场景起点读取。本轮恢复的是全部7个臂关节及夹爪开口；不是仅把夹爪移回某个空间点。归位使用原生关节位置控制器产生力矩，经正常 `env.step` 执行，没有传送机器人或物体，也没有在任务中重置场景。结束后恢复原OSC控制器和当前目标。

“归位完成”说人话就是：每个关节都回到初始角度附近，手指张开到初始开度附近，而且都已基本停住；连续五次动作后检查通过，才让 VLA 接手。具体阈值为关节角差≤0.01rad、关节速度≤0.02rad/s、指爪位置差≤2mm、指爪速度≤0.02m/s。

归位期间，所有具名物理物体的位移限制为5mm、转动限制为0.05rad；酒瓶目标保持、灶台关闭、空手检查完整。候选路线先在私有仿真副本上筛查接触，实际运动前后继续检查。两例均通过。采样筛查不能证明任意连续路径都无碰撞。

## 成功怎么确认

标准答案在实验前固定为“碗在盘子上、酒瓶仍在架上”，没有从 Hermes 临时计划生成。最终两例都满足这两个目标，夹爪没有抓着物体；原有 `release_verified` 完成机制还确认目标已释放、速度低于稳定阈值，连续五次动作后检查通过。奶酪位置及灶台保护也通过。

原始 `report.ok=true` 表示实验执行、记录和清理正常。任务成功另外看每例的 `physical_success` 和独立 `score.physical_gold_success`；本轮这两项在两例中都为真。[原始报告](pilot/report.json)、[预注册](pilot/preregistration.json)与[预先写定的计划](../../plans/2026-10-09-joint-home.md)可核对。

## 这个结果说明什么

它支持你提出的“做完一个任务，再完整归位，接着执行下一任务”方案：至少在这两个酒瓶→碗状态中，这种交接能与现有 SmolVLA 配合。机械臂离碗很近，并不等于处于 VLA 容易接续的起点；旧通用接近准备与完整归位的实际结果不同。

这使“先修交接／准备方法”比“立即微调权重”更有依据。它没有证明唯一原因就是关节角，也没有证明所有前序任务、物体位置或场景都适合归位。新条件同时改变了机器人姿态、开口、停稳过程和交接观测；任务后的场景仍与单任务起点不同。两例成功不能当作通用性已验证。

下一步适合把完整归位作为可选择、有限步数、有避碰和保护检查的标准交接方式，再小范围验证其它任务顺序。无需先训练；也不应该把“回原位”当作对任意场景都安全的动作。

## 实现与范围

GPT负责设计、接口核查、失败定位和验收；实际 DeepSeek API 编写[隔离归位模块](../../joint_home.py)与[行为测试](../../test_joint_home.py)，并按明确差异修正。本地执行者机械应用、运行、归档和Git；诊断runner由本地执行者按GPT固定流程编写。[来源记录](evidence/author_provenance.json)公开实际调用与拒绝记录，不含凭据。

一次全软件回归通过200项主体测试、31个子测试，退出码0。[原始软件日志](evidence/software.stdout.log)、[JUnit](evidence/software_junit.xml)、[摘要](evidence/software_summary.json)保留证据。

本轮只运行一次campaign、两例物理条件，约293秒。案例2有346步历史酒瓶重放＋243步归位＋93步新VLA＝682步；案例3有348＋241＋105＝694步，全部计数，没有隐藏补跑。历史重放用于恢复相同起点，不是重新评测完整Hermes对话链路。

使用原生 LIBERO/MuJoCo Franka 场景、已有 SmolVLA 权重、固定baseline_bf16配置和对应模型种子2／3，没有训练、微调、新权重下载或新增Hermes调用。已有生产源码与默认8081演示界面没有切换到这一归位方案；本轮是隔离对照实验。
